# WU-02 — Quality gates & test harness: plan

**Status:** approved (2026-11-02) · **Depends on:** WU-01 (done) · **Author:** main agent (Opus), 2026-11-02

## 1. Goal & scope

**Goal** (from `docs/work-breakdown.md`): every gate in CLAUDE.md §6.7 exists and runs, even with almost no tests yet.

**In scope**
- lefthook hooks: `commit-msg` (commitlint with the enforced scope list), `pre-commit` (lint + format on staged files, plus gitleaks), `pre-push` (`pnpm verify`).
- Vitest projects `unit` / `integration` / `functional` using the file patterns from §6.3, and v8 coverage with the §6.4 thresholds.
- Playwright configs for `apps/web-nextjs` functional tests and for `journeys/`, with `@axe-core/playwright` installed in the web app.
- Root scripts `test:unit`, `test:integration`, `test:functional`, `test:contract`, `test:journeys`, `verify`, `verify:integrated` and `verify:full`. Where the target doesn't exist yet, the script is a stub that prints what it skipped and which WU makes it real.
- At least one real test per Vitest project, proving the wiring. These tests also prove the WU's DoD on every run (D5).
- CI (`.github/workflows/verify.yml`) switched to run `pnpm verify`, as its comment already promises.

**Out of scope:** the `gen` drift check itself (WU-04; a stub is wired into `verify` now), the contract suite (WU-07/WU-12), journeys and the stack start script (WU-15), Playwright browser installation and any `*.spec.ts` (WU-12/WU-13 add the first ones), Next.js, Pact and `msw` dependencies, and the local Pact Broker.

## 4. Acceptance criteria → tests

WU-02 has no feature ACs (`docs/features/` starts in WU-05). Each DoD item maps to an automated test that runs on every `verify`:

| DoD item | Test | Layer |
|---|---|---|
| A non-conventional commit message is rejected; a conventional one with a valid scope is accepted | `scripts/commitlint.int.test.ts` (rule cases); `scripts/test/functional/git-hooks.test.ts` (the hook command as a process) | integration + functional |
| The scope list matches §10 | `scripts/commitlint-config.test.ts` | unit |
| A file containing a fake secret is blocked by gitleaks | `scripts/test/functional/git-hooks.test.ts` (staged fake token → non-zero exit; clean file → zero) | functional |
| Import boundaries still fire (carried over from WU-01) | `scripts/lint-boundaries.int.test.ts` | integration |
| `pnpm verify` runs end to end and passes | run by the main agent, plus CI on the PR | command |

Plus one manual smoke test at the end: a real `git commit` with a bad message is rejected by the installed hook (then nothing is committed).

## 6. Risks & open questions

- **Q1 — gitleaks install (needs your decision).** It isn't on this machine's `PATH`. **Recommended:** you install it once (`winget install Gitleaks.Gitleaks`), the wrapper fails loudly if it's missing, and CI downloads the pinned release with a checksum. *Alternative:* a `scripts/ensure-gitleaks.mjs` that downloads the pinned, checksum-verified release into `node_modules/.cache` on first use. That needs zero setup, but it's more code to maintain and fetches a binary from inside a hook.
- **Q2 — lefthook-native staged files instead of `lint-staged` (D4).** This differs from the work-breakdown's wording. If you'd rather keep `lint-staged`, it's a small change.
- **R1 — pre-push runs the full `verify`** (including `pnpm audit`, which needs network). It's slow-ish but it's what §6.7 asks for. `git push --no-verify` remains an escape hatch, which §6.7 doesn't forbid but which this repo should treat as an emergency only.
- **R2 — Vitest 5 + v8 coverage on near-empty source.** Placeholder `export {}` files should report 0/0 (treated as 100%); if v8 reports them otherwise, I'll exclude zero-statement files rather than lower a threshold.
- **R3 — gitleaks CLI flags** differ between versions (`protect` vs `git --staged`). I'll check them against the installed 8.30.1 and update D6 if needed.
