## 1. Goal & scope

**Goal** (work breakdown): prove the integrated system works for a user, and close the gate set.

**In scope**
- `tests/journeys/` gets its first specs: the four starting journeys of CLAUDE.md §6.6, each with one area tag and one criticality tag. The package keeps importing nothing from other workspaces.
- A stack runner, `scripts/run-journeys.ts`: builds both apps, starts `api-nextjs` (`LLM_MODE=replay`, hosted config, a fresh invite code) and `web-nextjs` pointed at it, runs Playwright in `tests/journeys/` with the arguments given, and stops both. No `BACKEND` variable (WU-19 note).
- `pnpm test:journeys`, `pnpm verify:integrated` and `pnpm verify:full` made real; the `skip.mjs` stubs go.
- `pnpm record:cassettes --journeys [filters]`: records the journeys' LLM calls (live, costs money, run once by the main agent with the user's go-ahead, §6).
- `pnpm record:cassettes --prune`: deletes cassettes no gated suite replays any more (WU-08 note, R5).
- `docs/features/journeys.md` with the ACs below; the README's Journeys row and the WU-19 section updated (wire-reorganization and WU-19 notes).

**Out of scope**
- Running the stack from the WU-20 container image (D9).
- New journeys beyond the four, performance testing, CI jobs for the integrated or full gates (CLAUDE.md §6.7: those gates stay local).
- Any change to the HTTP contract, the rule catalog, the `LlmClient` interface or the web UI.

## 2. Approach and key decisions

**D1. The runner mirrors `scripts/run-contract.ts`.** A thin `scripts/run-journeys.ts` with its decisions in a pure, unit-tested `scripts/journeys/plan-stack.ts` (as `contract/plan-run.ts`). It reuses `buildOnce` and `startApi` from `backends/api-nextjs/tests/support/` and `freshInvite` from `scripts/contract/plan-run.ts`, so the API runs exactly as the contract gate runs it (hosted config: `LOCAL_DEV=false`, a per-run code, generous limits). Rejected: Playwright's `webServer` for both apps. It can't build the web app *after* the API's port is known, and it can't prepare the cassette directory (D5). Scripts in `scripts/` may import workspace code; only `tests/journeys/` may not (§6.6).

**D2. Free ports, and the web app built against the API's URL.** `NEXT_PUBLIC_API_BASE_URL` is inlined at build time, so the runner picks the API port first, starts the API, then builds the web app with `NEXT_PUBLIC_API_BASE_URL=http://127.0.0.1:<apiPort>`, then starts it on a free port. The API gets `WEB_ORIGIN=http://localhost:<webPort>` so CORS matches. Free ports avoid clashing with a running `pnpm dev` (3000/4000). A new `scripts/journeys/web-server.ts` builds and starts the web app the way `api-server.ts` does the API (Node runs Next's bin directly; Windows `taskkill` on stop; signal handlers in the runner).

**D3. The journey build gets its own `distDir`.** `web-nextjs/next.config.mjs` reads `distDir` from `NEXT_DIST_DIR` (default `.next`); the runner sets `.next-journeys`. Otherwise a journey build overwrites the web functional suite's mock-API build in `.next`, and running `pnpm verify` and `pnpm verify:integrated` side by side would break one of them. `.gitignore` and the Vitest/ESLint excludes cover `.next-journeys`.

**D4. Deterministic dates through Playwright's clock.** Cassette keys hash the model request, which contains `referenceDate`, the browser's local date. Each journey calls `page.clock.setFixedTime('2026-11-16T12:00:00')` before navigating, and the config sets `timezoneId: 'UTC'` and `locale: 'en-US'`. Noon UTC keeps the local date the same in any zone the config could be changed to. Timers still run, so streaming is unaffected. The fixed date is a constant in `tests/journeys/support/clock.ts`.

**D5. Journey 4's 502 comes from a recorded request with its response swapped, in a temporary cassette directory.** This follows `AC-EXTRACT-15`'s precedent: nothing synthetic is committed. The runner copies `.llm-cassettes/api-nextjs/` to a temp directory, and for every cassette whose request body contains journey 4's message, swaps the response for an Anthropic `500 api_error`. The `LlmClient` retries once with the same body (same key), gets the 500 again, and the API returns `502 LLM_UPSTREAM_ERROR`. The runner fails with a clear message if no cassette matches (the marker drifted, or journey 4 was never recorded). The message is duplicated, with a comment in each place, in `tests/journeys/specs/upstream-failure.spec.ts` and `scripts/journeys/plan-stack.ts` (journeys can't import the runner, and the runner shouldn't import a spec). Rejected: `page.route` faking a 502 in the browser (that is the web functional suite's job, and the journey would no longer exercise the backend's error path); a cassette miss (that is a 500 bug, not a 502).

**D6. Recording journeys.** `pnpm record:cassettes --journeys [filters]` runs the runner in record mode: the API gets `LLM_MODE=record`, `LOCAL_DEV=true` (`freshInvite(..., { recording: true })`, as for `--contract`), the real cassette directory, and no swap. Journey 4 cannot pass while recording (its call succeeds), so it declares `test.fail(process.env.JOURNEYS_RECORDING === '1', …)`; the runner sets that variable only in record mode. It is an environment variable, not an import, so §6.6 holds. Recording is never a gate.

**D7. Invite code entered as a user would.** The runner passes the fresh code to Playwright as `JOURNEY_INVITE_CODE`. Every journey sends its first message, waits for the "Invite code" field (the UI shows it only after a 401; WU-13 note) and submits the code, which retries the turn. A shared `support/start-trip.ts` does this for all four, so the 401 path is exercised once per journey at no extra cost. Rejected: `/?invite=<code>` (skips the real 401 flow; covered by `AC-CONV-11` already).

**D8. Locators and waits.** Role and label locators only, no fixed sleeps (§6.6). Status lookups are scoped to their region ("Conversation", results), since the page has two status lines and Next's route announcer (WU-14 note). Journey 1 ends at "Your recommendations are ready." with card headings at level 3 (WU-14 note). Journeys never assert model prose, only structure (a clarification is shown, the "What needs fixing" list names the rule, cards exist), because re-recording may change the words.

**D9. No container-image mode.** The work-breakdown note asks whether the stack can also run from the WU-20 image. Not in this unit: `pnpm test:image` already runs the provider contract tests against the container in CI, the default path must need no Docker, and the web app has no image yet. A `--image` flag can come with WU-23 if wanted; proposed as a Note on WU-23.

**D10. Axe at each journey's end state.** Per the WU-13 note, each journey runs one `@axe-core/playwright` scan on its final state, after waiting for `document.getAnimations()` to finish (copied, not imported). This catches a11y issues that only real model text can cause (long names, odd markup) at no extra journey cost. `@axe-core/playwright` 4.14.0 (the version web uses) is added to `@vp/journeys`.

**D11. Gate commands.**
- `test:journeys` → `node scripts/run-journeys.ts` (extra arguments go to Playwright, e.g. `--grep "@smoke|@critical"`). `--pass-with-no-tests` is dropped (WU-02 note).
- `verify:integrated` → `pnpm test:journeys --grep "@smoke|@critical"`. The runner builds both apps, so "build all, start the full stack" is one command (§6.7).
- `verify:full` → `pnpm test:journeys --grep @full && pnpm test:contract` (WU-19 note: journeys `@full` plus the provider contract tests against api-nextjs).
- The integrated and full gates stay local; no CI job is added (§6.7). Playwright needs Chromium installed once (`pnpm --filter @vp/journeys exec playwright install chromium`; WU-14 note); the README says so.

**D12. Pruning cassettes (WU-08 R5).** In replay mode, `cassette-fetch.ts` appends each hit key to the file named by `LLM_CASSETTE_USAGE_LOG`, when set (one line per hit; no effect otherwise). `pnpm record:cassettes --prune` runs, in replay mode with that variable set: the `integration` and `functional-api` Vitest projects, `run-contract.ts`, and `run-journeys.ts` (all four journeys). If all pass, it deletes every cassette in `.llm-cassettes/api-nextjs/` whose key isn't in the log and lists what it deleted; if any fails, it deletes nothing. It makes no live calls. The functional 502 tests read their source cassette with `readdir`, not through the fetch, so the prune also keeps any cassette whose request body contains a marker those tests and D5 look for; the markers live in one list in `scripts/record-cassettes/prune.ts`, with a test asserting that every source cassette is kept. The user reviews the deletion as a git diff before committing.

**D13. Flakiness check (DoD).** Three consecutive runs of `pnpm verify:integrated` and `pnpm test:journeys --grep @full` on a clean tree, reported with their output; plus one network-off run of `pnpm verify:integrated` (§6, R3).

## 6. Risks & open questions

**Risks**
- **R1 — Recorded prose changes.** Re-recording can change model wording. Journeys assert structure only (D8), and the clarification for journey 2 is identified by the catalog-worded violation text, which comes from code, not the model.
- **R2 — The model doesn't produce the path a journey needs.** E.g. the "vague" request comes back `ready`, or the answer still needs clarification. Messages are chosen so rules decide it (fewer than 3 populated fields ⇒ `INSUFFICIENT_DETAIL`; a child aged 19 ⇒ `CHILD_AGE_RANGE`). If a recording still goes the wrong way, I adjust the message and re-record (a few cents), and log it as a deviation.
- **R3 — "No network access to Anthropic" is proven by construction, plus one real run.** Replay mode never calls the network and the API key is blank. A dead proxy can't prove it (WU-08 deviation 7), so the DoD run with the network off needs you to switch Wi-Fi off for a few minutes, or I report it as by-construction only (Q3).
- **R4 — Slow gate.** Two `next build`s per run (~1–2 min) plus the journeys. Acceptable for a manual gate.
- **R5 — The prune's marker list** must track the functional 502 tests. A test fails if a marker's source cassette would be deleted, so drift is loud.

**Open questions**
- **Q1 — Recording budget.** May I run `pnpm record:cassettes --journeys` with your `ANTHROPIC_API_KEY` during the build (estimated well under $1; I'll report the cost from the logged usage)? *Recommended: yes.*
- **Q2 — Journey 4's area tag.** Fail the first extract (`@clarification`, simplest, one cassette) or `/recommend` after a `ready` profile (`@recommendation`, longer journey, still one swapped request)? *Recommended: fail the extract* — the backend error path and the UI's Retry are the same either way, and `/recommend`'s 502 is already covered by `AC-RECOMMEND-18` and the web functional suite.
- **Q3 — Network-off run.** Will you toggle Wi-Fi off for one `pnpm verify:integrated` run (I'll start it in a terminal tab), or accept "by construction" for that DoD item? *Recommended: the real run.*
- **Q4 — Prune in this unit?** It's a Note from WU-08, not in the Scope list. *Recommended: yes* (T5 is small and independent); otherwise it moves to WU-16 as a Note.

## Deviations during implementation

1. **The web app runs on `127.0.0.1`, not `localhost` (D2).** The runner starts web-nextjs on `127.0.0.1:<port>`, and the API's `WEB_ORIGIN` names that address. Binding one address avoids `localhost` resolving to `::1` in Chromium while the server listens on IPv4 only. Not material.
2. **AC-JOURNEY-09 is narrower.** "Deletes nothing when a suite failed" is ordering in `scripts/record-cassettes.ts`, not a pure function, so it isn't unit-tested. `docs/features/journeys.md` says so; §4 above still lists it. Not material.
3. **T5 also touched `backends/api-nextjs/src/llm/index.ts`.** That is where the replay options are built, so it reads `LLM_CASSETTE_USAGE_LOG` there and passes `usageLog` to the cassette fetch. Not in §3's file list. Not material.
4. **`tests/journeys/tsconfig.json` adds `"lib": ["ES2023", "DOM"]`**, for `document.getAnimations()` in `support/axe.ts`. Not material.
5. **Journey 2's first recording run failed on its locator, not on the recording.** The violation list has no accessible name, and each turn is a list item too, so `/child's age/i` matched two items. The spec now matches the list item that holds no nested list. Its calls were recorded on that run, so nothing was re-recorded. Not material.
6. **Recording cost about $0.03** (Sonnet 5.5: 2 calls; Haiku 5.5: 12 calls; totalled from the cassettes' usage, because the runner doesn't echo server logs).
7. **The prune deleted 1 of 52 cassettes: a new, never-committed one.** It was journey 4's clarification call. It was recorded, but in replay the extract fails first, so no suite replays it. 13 new cassettes remain. No committed cassette was deleted.
8. **The kept-marker list holds one functional-test marker.** `'Somewhere warm, maybe.'` (extract.test.ts) is the only single string a 502 test uses. The recommend and present 502 tests pick their source by several conditions, and their sources are replayed unchanged by the happy-path tests, so the usage log keeps them anyway.
9. **Journey 1's level-3 heading check is page-wide.** The results section is named by a dynamic h2, so it has no stable region name. Only cards use h3.
10. **New commit: `fix(contract)` for a self-test that fails on macOS 27 (user's choice: fix in this unit).** `pnpm verify` failed on clean `main` too: "AC-CONTRACT-09: a 413 sent before the upload ends, then a socket close, passes" got `write EPIPE`. The fake's early-413 mode set `Connection: close`, and Node's server destroys a socket whose response finishes while the request is unread. Upload data arriving after that drew a TCP reset, which on macOS 27 can discard the 413 before the client reads it. The fake now writes the 413 at once but finishes the response, and ends the socket, only after draining the upload (a lingering close, as real servers do). `postOversized` uses `agent: false`, so a socket the server closed after an earlier 413 is never reused (`socket hang up`). 12 consecutive passes after the fix; CI (Linux) never showed it.
11. **Commit order changed.** `prune.ts` imports journey 4's marker from `scripts/journeys/plan-stack.ts` (fix 5), so the runner commit comes before the prune commit, and the contract fix comes first.
12. **README:** besides the Journeys row and the gate commands, the stale sentence "The backend, web client and journeys are scaffolds until their work units land…" is removed.
13. **`--contract` with `--project` now errors (unit review finding 2).** Before WU-15, `--project` was silently ignored next to `--contract`; the new mutual-exclusion check rejects it, and `plan.test.ts` covers it.
14. **Deviation 2 is reversed (unit review finding 4).** The rule "run every suite, delete only if all passed" moved into `afterAllPass` in `prune.ts`, with two tests, and AC-JOURNEY-09 states it again. That one-line change to `docs/features/journeys.md` landed in the prune commit, after the runner commit had added the file (fixed forward, never amended). The real `--prune` re-ran clean afterwards (0 of 51 deleted).
15. **The network-off run** was automated, because the user can't message the session with Wi-Fi off: a background script waited until `api.anthropic.com` was unreachable, ran `pnpm verify:integrated` (exit 0, both journeys passed), and confirmed the network was still off at the end.
