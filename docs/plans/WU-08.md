## 1. Goal & scope

**Goal** (from `docs/work-breakdown.md`): a deterministic, cost-free LLM boundary for all tests (CLAUDE.md §6.1, §8.3).

**In scope**
- The `LlmClient` interface in `src/usecases/`, shaped by ADR 0001.
- An AI SDK implementation in `src/llm/` with per-role model selection, ADR 0001's call defaults, the single retry, refusal and parse-failure mapping to `LlmError`, and `safeParse` of every output (§7).
- A cassette `fetch` for `record` / `replay`: files in `.llm-cassettes/`, keyed by a SHA-256 of the request body string. Request headers are never written, response headers are allowlisted, streams are recorded without buffering, and replay re-emits SSE events as separate chunks.
- A replay miss is an error carrying "re-record with `LLM_MODE=record`". It is never retried, and nothing falls through to the network.
- `mock` mode built on the AI SDK's `MockLanguageModelV4`. A mock can return a given, schema-checked value per stage, which is what WU-09's rule-fixture test needs (WU-07 Note, ADR 0002).
- Usage and latency logging for every call.
- Making the gates incapable of going live: Vitest forces `LLM_MODE=replay`, a guard blocks non-loopback `fetch` in test processes, and recording has its own script.
- One recorded live call, committed as a cassette and replayed by an integration test.
- Feature doc `docs/features/llm-client.md` (§6.2).

**Out of scope**
- Any stage prompt, or wiring the client into a route. WU-09 adds `/extract`, its prompts and its cassettes. The stubs stay as they are.
- **A streaming method on `LlmClient`** (see Q1). Streaming is proven at the `fetch` layer here. WU-11 adds `streamObject` to the interface along with its mid-stream error semantics.
- Pruning stale cassettes (see R5).
- `pnpm eval` (§6.8).

## 2. Approach & key decisions

| # | Decision | Why / CLAUDE.md | Rejected alternative |
|---|---|---|---|
| D1 | **Interface** (`src/usecases/llm-client.ts`): `interface LlmClient { generateObject<T>(req: LlmObjectRequest<T>): Promise<T> }`. The request is `{ stage, role, schema, system, prompt, maxOutputTokens, effort }`. `stage` is `'extract' \| 'clarify' \| 'recommend' \| 'critic' \| 'present'` and is used for logging and mock lookup. `role` is `'fast' \| 'reasoning' \| 'critic'`. `schema` is a Zod schema; Zod is allowed in use cases, the AI SDK is not. `effort` is `'low' \| 'medium' \| 'high'`. All fields are required, so no stage can forget `maxOutputTokens`. It returns the validated value or throws `LlmError`. WU-09's clarification text uses a one-field schema (`{ question: string }`) instead of a separate text method. | §7 one interface for every stage; §9 the interface lives in use cases and is free of the SDK; ADR 0001 Decision (`maxOutputTokens` and `effort` on every call). | Passing SDK `LanguageModel` or `providerOptions` through: leaks the SDK into use cases (lint blocks it). A `generateText` method for plain strings: a second code path with its own failure handling. |
| D2 | **AI SDK implementation** (`src/llm/ai-sdk-client.ts`): `createAiSdkLlmClient({ modelFor, log, now })`. `modelFor(role)` returns a `LanguageModel`. Each call runs `generateText({ model, system, prompt, output: Output.object({ schema }), maxOutputTokens, maxRetries: 0, providerOptions: { anthropic: { structuredOutputMode: 'outputFormat', effort } satisfies AnthropicLanguageModelOptions } })`. It never sets sampling params. It checks `finishReason === 'content-filter'` **before** reading `output`, then runs `schema.safeParse(result.output)`. | ADR 0001 Q2, Q4, Q5; §7 "LLM output is untrusted input"; §8.2. | `generateObject` (deprecated). Trusting `Output.object`'s validation alone: §7 asks for an explicit `safeParse`. |
| D3 | **Failure policy, one attempt plus at most one retry:** <br>• Refusal (`content-filter`) → `LlmError('LLM_REFUSAL')`, not retried. <br>• `NoObjectGeneratedError`, a failed `safeParse`, or an `APICallError` with `isRetryable` → retry once, then `LlmError('LLM_UPSTREAM_ERROR', { cause })`. <br>• Non-retryable `APICallError` (4xx) → `LLM_UPSTREAM_ERROR` at once. <br>• **`CassetteMissError` anywhere in the `cause` chain → rethrown as is**: not retried, not wrapped in `LlmError`, so it surfaces as a test failure or a 500, never as a 502. <br>• Anything else → rethrown (a bug, so a 500). | ADR 0001 Q5 Decision; §6.1 "a cassette miss is a test failure". The SDK wraps errors thrown by `fetch`, so the miss has to be found by walking `cause` (verified in T4, R1). | Retrying a refusal: the ADR rejects it. Mapping a miss to 502: it would look like an upstream outage and hide the re-record instruction. |
| D4 | **Cassette format.** One file per exchange at `<dir>/<sha256(body)>.json`: `{ key, request: { method, url, body }, response: { status, headers, body } \| { status, headers, sse: string[] } }`. `request.body` is stored as parsed JSON so diffs are readable. **Request headers are never written**, which removes `x-api-key` by construction. Response headers are allowlisted to `content-type` and `request-id`. SSE bodies are split on blank-line event boundaries into `sse[]`. Files are written as `JSON.stringify(…, null, 2)` plus a newline, which is Prettier-stable; `.llm-cassettes/**` is already lint-ignored. | §6.1, §8.2; ADR 0001 Q6 (allowlist, body-string key, user agent not in the key); work-breakdown Notes. | A denylist of headers: the spike's first captures leaked account IDs that way. Keying on headers or URL: an SDK patch bump would invalidate every cassette. |
| D5 | **Cassette fetch** (`src/llm/cassette-fetch.ts`): `createCassetteFetch({ mode: 'record' \| 'replay', dir, network? })`. <br>• **Replay** reads `<dir>/<key>.json` and has **no access to the network**: `network` is not accepted in replay mode. JSON bodies come back as one `Response`. SSE bodies come back as a `ReadableStream` that enqueues each event as its own chunk. A miss throws `CassetteMissError` with the key, the model from the body and "re-record with `LLM_MODE=record`". <br>• **Record** calls `network` and returns the response **immediately**. It reads `response.clone()` in the background and writes the file when the body ends. `flush()` returns a promise for the pending writes, so a recording run can await them. **Only 2xx responses are written.** Any other status is passed to the caller unrecorded, with a `console.warn`, so a 529 during recording can't become the committed cassette (review #3). **Each key holds exactly one exchange**: a retry with an identical body overwrites the file, so the last 2xx wins. A "bad first attempt, good retry" sequence can't be replayed from cassettes; the T4 tests cover retries with an in-test fake `fetch`. | ADR 0001 Q6 pitfall (buffering); §6.1 "never silently fall through to live". | A replay that falls back to `globalThis.fetch`: exactly what §6.1 forbids. Writing files from an `afterAll` hook: couples the recorder to Vitest. |
| D6 | **Mock mode** (`src/llm/mock.ts`): `createMockLlmClient(responders, deps)` reuses `createAiSdkLlmClient`, with `modelFor` returning a `MockLanguageModelV4` (`ai/test`). A responder is keyed by `stage` and returns a `MockReply`: built with `mockObject(schema, value)`, which **`safeParse`s at construction** and throws if the value is invalid (§6.1), or `mockRefusal()`, or `mockRaw(text)` for malformed output. The mock model turns a reply into `doGenerate` content or a finish reason, so mock mode runs our real `generateText` / refusal / retry / `safeParse` code. A stage with no responder throws `MockNotConfiguredError` (a bug, so a 500). | §6.3 unit layer "`LlmClient` = mock model"; WU-07 Note: WU-09 needs a mock that returns a given extraction. | A hand-rolled object implementing `LlmClient`: it would skip the real adapter code, so use-case tests would prove less. |
| D7 | **Factory** (`src/llm/index.ts`): `createLlmClient(config, deps?)` picks the mode. <br>• `live` → `createAnthropic({ apiKey })` with global `fetch`. <br>• `record` → the cassette fetch over global `fetch`. <br>• `replay` → the cassette fetch with no network. `createAnthropic` gets a dummy key (`'replay'`), because no request leaves the process. <br>• `mock` → `deps.mockResponders` is required, and missing it throws `ConfigError`-style at construction. <br>Models come from `config.models[role]` (§8.1). WU-09 calls the factory from its route wiring. | §8.1–8.3; §9 the implementation lives behind the interface. | Default server-side mock responders for `pnpm dev`: not needed until there is a real stage (the stubs cover dev until WU-09–11). |
| D8 | **Config:** `cassetteDir` comes from `LLM_CASSETTE_DIR` if set. Otherwise it is the nearest ancestor of the working directory that contains `pnpm-workspace.yaml`, joined with `.llm-cassettes/api-nextjs`. The per-backend subdirectory keeps FastAPI/Go cassettes apart (Q3). `loadConfig(env, { cwd, exists })` takes the working directory and an existence check as parameters, so it stays pure and AC-LLM-18 doesn't depend on the real file layout; `getConfig()` passes `process.cwd()` and `existsSync` (review #1). `tests/support/api-server.ts`'s `baseEnv` pins `LLM_CASSETTE_DIR` to the repo's `.llm-cassettes/api-nextjs`, so a developer's `.env.local` can't redirect functional or contract servers (review #1). `.env.example` documents the variable. | §2 layout; tests and `next start` run from different working directories. | `import.meta.url`: points into `.next/server` after a build. |
| D9 | **Logging:** each call emits one `LlmCallLog` to `deps.log`: `{ stage, model, role, outcome: 'ok' \| 'refusal' \| 'retry' \| 'error', inputTokens, outputTokens, latencyMs, warnings, attempt }`. Latency comes from an injected `now()`; the factory passes `performance.now`. The default `log` prints one line with `console.info` (§8.3 "to the console in dev"), and `warnings` are always included. | §6.1 no wall-clock reads in tested logic; §8.3; ADR 0001 Q4 (warnings visible). | Throwing on warnings: a provider deprecation would then break production. Integration tests assert warnings are empty instead. |
| D10 | **Gates can't go live.** <br>• Recording is allowed only when `VP_LLM_RECORD=1` **and** `npm_lifecycle_event === 'record:cassettes'` (pnpm sets this per script), so exported shell variables alone can never make `pnpm verify` record (review #2). ## 6. Risks & open questions

**Questions for you**
- **Q1: Streaming method now, or in WU-11?** I recommend **WU-11**. The recorder and replayer are proven for streams here (D12), but `streamObject`'s contract depends on mid-stream error behaviour, which ADR 0001 leaves to WU-11. Adding it now would freeze an interface before that design. The cost is that WU-11 changes the `LlmClient` interface, so its review tier becomes `opus` under the start-wu rules. I'd add a Note there.
- **Q2: The live recording.** It needs `ANTHROPIC_API_KEY` in the root `.env.local`. I'll stop and ask before running it. Is a key there, or will you add one? The expected cost is under one cent.
- **Q3: Cassette subdirectory `.llm-cassettes/api-nextjs/`.** I recommend it. FastAPI/Go send different request bodies, so their cassettes never collide, but separate folders keep each backend's set reviewable and prunable. The alternative is a flat `.llm-cassettes/`, matching §2 literally.
- **Q4: The network guard (D10)** goes slightly beyond the listed scope. I recommend it, because it turns the DoD "passes with the network disabled" into something checked on every run rather than once.

**Risks**
- **R1: The SDK's wrapping of `fetch` errors.** A throw from a custom `fetch` probably reaches us as an `APICallError` (retryable, as a network error) with our error as `cause`. D3 walks `cause`. T4 proves this first; if the SDK drops the cause, I'll pause and tell you.
- **R2: `ai/test` in non-test code.** `mock.ts` imports `MockLanguageModelV4` from `ai/test`, which Next would bundle into the server. If `ai/test` pulls in a test runner or breaks `next build`, the fallback is a small hand-written `LanguageModelV4` mock in `src/llm/mock-model.ts`. I'd record that as a deviation.
- **R3: Cassette key stability.** The key is the exact body string the SDK serializes. Changing the prompt, schema, effort, model or SDK body shape invalidates it, which is intended (ADR 0001 Q6). An `ai` minor bump that reorders body fields would need re-recording, and replay misses say so loudly.
- **R4: The background write race in record mode.** If the process exits before a stream's clone finishes, the cassette is lost. `flush()` handles this, and the record script's tests await it in `afterEach`.
- **R5: Stale cassettes.** Nothing deletes cassettes whose prompts have changed. That's harmless for correctness, but it adds clutter from WU-09 on. I'd propose a Note for WU-15 (`record:cassettes --prune`), not build it here.
- **R6: `pnpm audit --prod` on the new runtime deps.** A new advisory would block `verify`. If one appears, I'll bring it to you rather than pin around it.
